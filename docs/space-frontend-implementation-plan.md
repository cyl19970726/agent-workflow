## 当前阶段：普通 CONTENT 新业务闭环

用户授权推进下一步，并确认复用 Kimi/GLM 历史一手材料新建普通委托。**本阶段应让人从新建业务走到可读产物和可恢复的处理建议，无需先创建 A/B 计划。** 这是新 Case、新运行和新稿，不声称选题此前未做，也不验证另一项方法改动。全文核对材料后，认知侧发现先前建议的“弱老师训练强学生”缺少直接证据，已将工作题目校正为“同一个基础模型，为什么后训练还能让它变强？”。用户确认的是材料选择；题目属于认知侧在授权业务范围内负责的可逆输入设计，不冒称用户已认可，也不额外要求批准。实际发起前再核对用户最新指令和准确输入。

实用起点：本阶段开始时，新界面的业务页只能选择已有 Case，启动入口仍依赖验证计划。既有服务已经有创建 Case、导入资产、冻结输入及准确排队能力；缺口是普通命令协议、业务表单和持久处理建议的接入。用户确认的旧数据归档与旧格式兼容清理已先行交接：当前在线默认两版 CONTENT 方法、一个 MiMo Case、两次 CONTENT 运行及30份资产；两次独立判者运行与完整意见链保留。此前测试/原型历史转为离线可恢复归档，54表恢复摘要及备份哈希已核对；必要祖先身份保留但退出默认列表。旧4393控制台和4396原型服务已关闭，当前入口为4397。保存历史证据不等于永久维护旧产品格式或保证旧URL继续可用。

本轮复用已有 Case、不可变输入、schema 资产和共享服务。普通业务写动作独立于验证计划命令，creation 只供领域输入与阅读器。文本材料满足本次需求，不以通用附件、对象存储、完整草稿修订系统为前置条件。首轮使用前一次候选的 CONTENT 方法内容，不把重新登记部署版本描述为质量提升。

处理建议先用 `creation/content-handling-note` 一类领域导入资产，关联准确 Case/run/稿件及所引用意见；提供可靠的归属查询和重开入口。外部认知会话身份属于声明来源，实际导入者由服务鉴权记录；不能写成已核验的节点判者，也不能冒充人类评价。该建议不是接受、采用或发布。既有可信 `review` 合同保持不变，不强迫每个普通业务额外运行独立判者。写接口校验对象关系，追加建议不覆盖历史，重试幂等。

实际调用边界：root 核对最终部署、准确输入、角色模型及派发范围后，从界面启动最多一次新业务运行；全部 CONTENT 角色沿用已授权 `gpt-5.6-luna/high` 与现有 SIWC 订阅路线，最多两次改稿。Kimi/GLM 材料核验日期为 2026-09-28，关闭新增联网。额度或基础设施阻断保留证据并停止，不自动重试、替换模型、计费或扩样。没有实际产物则本阶段未完成；有产物但不达标可记录需修改，而不是强行接受。

执行 session 先交付工程与 preflight，认知侧再实际使用及读稿，必要修复沿用同批。私有约定及回执目录为 `.local/cognition-loop/ordinary-content-20261007/`，当前协调状态在 `.local/cognition-loop/state.json`。审阅建议来源和跨轮一致性仍是另一项待验证方法假设，本阶段不自动再跑 MiMo A/B。B3、多 workflow、VM、后训练、完整运营与外发继续不在本次范围。

## 下一阶段的完整目标：真实使用与一次有证据的改进

以下是前一阶段的原约定；2026-10-07 已按开头所述限定范围完成。

2026-10-06 晚，用户告知已开启应用使用 ChatGPT 额度，要求认知侧实际使用工作台后定义下一阶段目标。再次实用私有原型与现有服务后，本次认知提出的阶段目标是：**在同一个真实 Workflow Space 中完成一件 CONTENT 业务的执行与审阅，依据准确资产形成改进假设，完成一次有边界的方法验证，并留下别人可以接手的结论。** 批次 A 是第一个工程里程碑；只读接入完成不足以结束这个阶段。用户已授权审计无阻断后执行；先实施批次 A，真实推理在准确部署与条件核对后进行，不把授权当成已运行。

范围取批次 A、批次 B 的单案例最小业务路径，以及批次 C 中已有问题／计划／比较能力的最小接入。保留 A/B/C 的工程拆分，不要求先完成全部运营看板再验证一次改进。沿用 MiMo 及已保存材料；本阶段的证据只能支持该案例，不声称跨案例成熟、已稳定运营一周或已得到用户认可。

| 阶段成果 | 人和认知 Agent 应能实际完成 | 验收边界 |
| --- | --- | --- |
| 理解当前方法 | 从 Space 找到目标、标准、正在查看／当前采用／可执行版本，沿图理解职责、输入输出、返工与停止 | 最新候选无运行时仍有方法说明及已有 Case 入口；未采用不伪装为默认生产方法，也不强制先采用才能验证 |

| 形成可接手的改进 | 认知 Agent 经现有 CLI 取准确输入、资产和执行证据，记录问题类别、假设、拟改节点、基线与验证条件；界面能读回 | 内部审阅意见是证据，独立认知结论另记。仅写出假设属于准备，不能登记成已验证的 iteration |

| 保存结论并可接手 | 在 Space 中恢复本次业务处理结果、两版差异、评价、问题、比较和下一步；保留基线、待验证、建议采用分别说明 | 自动化可保存判断和建议；用户接受作品、采用方法和外发仍按各自授权执行。重开页面或换操作者不需重读整段聊天 |

已有评价、验证计划、issue、comparison 与 iteration 底层继续复用。当前 `recordIteration` 要求已有评价和候选验证运行，尚未运行时用适当的问题／计划记录承载假设，不为“画一条演进边”伪造完成态。评价者身份如实记录为用户或 Agent，认知 Agent 的意见不能写成用户意见。

本阶段的“需修订”先使用已有四问／问题记录表达为有来源的评价结论与下一步；当前 CONTENT 稿件合同只有候选到人工接受的状态转换，不能凭界面标签写入不存在的状态。独立 Agent A 走可信节点评价入口，网页的人类评价表单不能替它落库。保存不满意和改进判断不以用户接受、改写资产状态或新增完整处置系统为前提。

独立审计补充的结论边界：Agent A 不得用自身知识替稿件补全解释；即使候选胜出，也只支持它更满足本次冻结标准，不能据此宣布普通观众需要同等理解深度。“评价要求可能过深”继续作为未排除的解释，需要真实受众证据才能进一步判断，不在本阶段伪造解决。

### 先做什么，以及何时停止

1. **先交付批次 A 的真实数据路径。** 同时补本次实际体验暴露的必要交互：定义节点默认说明职责与合同；首次输入与返工输入有明确时机；运行节点默认本轮状态／产物；从作品直接读对应意见并返回。此项通过只记“真实只读贯通”。
2. **接入单案例动作与审阅。** 准备／复用材料、显式运行、异常处理、两稿并看、四问与本次处理决定使用同一对象上下文。新增前端不另造存储；旧服务已有的动作按权限接入，缺少的草稿／交付语义才补领域合同。
3. **把一项改法做到有验证结论。** 最小验证入口接入现有计划、问题、比较和有证据的演进记录；方法修改仍由 Agent + CLI 完成。完整七天运营、跨案例质量排名、通用编辑器、自动采用不是本阶段前提。

额度设置变化后，先检查基线／候选的准确部署指纹、输入、标准与判者，再开始有界 Luna/high 调用；首个基线请求也可兼作可用性核验，不必额外消耗一次模型调用。若指纹变化，新建不可变版本和关联计划，保留旧失败；基线先完成，候选才继续。再次额度拒绝或基础设施阻断时停止，不循环重试、不切模型或计费。若基线和候选质量无差别或候选退步，记录结论即完成该假设的验证，不自动扩大样本或无限改稿。

原 MiMo 模型支线与新界面验收分别记账。模型支线可先恢复，但最终必须有至少一次经新工作台显式发起、跟进、审阅的真实路径；基线可由 CLI 新跑，将计划中的候选运行安排为该路径，避免重复付费运行。两次运行仍须满足同一冻结计划的条件，不能为迁就界面进度静默替换部署版本。旧三稿及历史额度失败继续用于只读和异常场景验收，不能冒充本阶段配对的新证据。

### 本阶段不包含的承诺

不新增 B3、多个主 workflow、VM 调度、模型后训练、DeepSeek 切换、通用拖拽编排、完整多用户部署或大媒体平台；不伪造七天数据。完整跨案例运营、分布观察与第二业务复用保留为后续目标。技术路径可用、模型确实运行、作品质量达到什么程度、用户是否接受四项分别汇报；“有证据地判定此改法无效”是有效结果，“没有任何可评估产物”则仍是阻断。

## 完成定义

用户需要在同一个 Space 中完成两条闭环：用准确方法完成业务 Case、产出可读资产、协作评价并交付反馈；在稳定使用后复盘阶段资产与质量问题，提出方法改变、跨案例验证并明确采用。默认工作流／业务／资产三个一级入口与就近评价，工作流内方法定义／单次执行／运营观察／版本演进四视图承载这些任务；菜单不是完成闭环的证据。原型的独立“评价与迭代”入口是过渡，不要求本轮反复改导航。

基础约束：通用实现放 vendor，共享服务仍为事实源，creation 只注册领域语义，不迁移研究／分析 UI；历史版本、运行、资产与私有材料保留。产品设计与验收复核由认知侧维护，技术实现与集成由执行侧承担；并行文件归属须明确。

当前先实现其中一条最小真实路径：已有 MiMo Case 的冻结计划运行与就近审阅，不因此宣称下表全部日常业务能力已交付。运行前确认区先显示业务目标、所选方法、材料数量、运行条件及下一步动作；完整目标与必答问题可直接阅读。版本 ID、清单 hash、schema 和任务技术记录收进可展开的追溯详情，状态使用用户能理解的词语。开始按钮及不能开始的原因在默认视口可见，不能因嵌套滚动或布局压缩隐藏；展开长材料不得挤掉目标摘要或让流程图失去主要位置。这些要求来自本轮实际使用发现，应由真实浏览器任务验收。

## 批次 C：稳定使用后的复盘与方法迭代

交付：明确方法作用域、运营窗口、关键阶段资产集合；版本演进图、评价/问题聚合、验证集合、对照与采用。

1. 保存首版业务契约与设计理由：目标、标准、阶段、节点职责、预期产物与停止条件，首版无 predecessor 仍可说明依据。稳定采用版与候选研发并行，分别筛选。
2. 版本按真实 predecessor 画图，显示改动依据和环境／Prompt／模型／流程变化；无前驱的保持独立，登记和采用分开。
3. 从采用方法的一周等明确窗口筛 Case/run 和阶段资产；区分执行可靠性、业务质量、接受与交付反馈，指标带分母／评价覆盖与缺失。
4. 冻结复盘对象与条件，展示已有 review、issue、iteration、validation plan、comparison，不用一份 manifest hash 代替所有条件。
5. 对照先显示输入、Case 约束、effectiveConfig、标准与 judge 的变化；支持同 run 稿件、跨 run 结果和跨方法验证三种对象。
6. 认知 Agent 可经共享 CLI/skill 留下问题、假设与新版本依据，UI 能读同一记录；下一版由明确授权采用／回退，不自动把登记当采用。

复盘窗口及设计理由没有独立持久语义时新增合同，不从时间顺序猜因果。首期可由 Agent + CLI 改代码／Prompt 并发布，UI 阅读和采用；通用拖拽编排与模型后训练不作为这一批前提。

真实路径验收包含“V2 最近 7 天 → 研究节点 → 各 Case 研究资产 → 按明确维度看好／差／未评价 → 并看 → 回 run”；版本边展开问题、假设、改动节点、验证得失、采用与运营反馈。一周仅是观察窗，没有改善证据可继续用基线，不强改。

真实验收：稳定版本筛选范围不混入候选失败；阶段资产列表能进入准确例子与评价；每次方法改动可追到问题／证据；未启动候选、未形成比较、未采用均明确；采用 scope/slot 不误用资产 adoption。

## 整体首期验收

批次 A、B、C 的相关真实任务通过后，再由认知与用户验证业务闭环和改进闭环。技术构建／离线测试／浏览器交互／模型执行证据／业务质量／人类接受分别报告。

最低任务包括：初建目的与标准、首版看方法、发起并完成 Case、读阶段资产、处理一次异常、评价接受和交付反馈、按版本／窗口复盘、形成有依据的候选及验证、明确采用或保留基线。用同一组准确对象走完整条路，不能拿几个互不相干的页面截图代替验收。
