## 使用入口

Space 的“工作流”进入版本列表；候选预览位于 `/workbench/workflows/preview`。发布后的准确方法页位于 `/spaces/:spaceId/workflows/:workflowVersionId/:entrypoint`，包含流程与节点、选题与运行、已有评价和版本变化。

候选预览不写数据库、不创建 run、不调用模型。发布后即使零运行也有完整方法页。后续版本须选择兼容前驱，允许从旧版本分支，不自动把最近发布当作当前采用。节点配置分别保存业务声明与实际执行器能力；CONTENT 当前宿主保存 SIWC 工具及执行限制，不把业务权限声明误写成实际可用工具。

CLI 提供 `method-preview` 和 `method-publish`，具体参数见 [creation 使用入口](https://github.com/cyl19970726/creator-lab/blob/main/workbenches/creation/docs/README.md)。CONTENT 开始运行前要求当前准确候选已经发布；历史 ID 对应的执行代码不可用时明确说明，不用当前代码冒充旧版。

## 共享与业务边界

共享 `agent-workflow` 提供版本身份、冻结节点定义、流程与数据绑定校验、通用 SVG、版本查询及发布 UI。creation 提供 CONTENT 节点、业务 schema、prompt、模型／工具配置和发布宿主。本轮未改变 CONTENT 的业务 prompt、路由或评价标准。

流程合同新增可选 `runInputs` 与 `dataBindings`：区分冻结输入、当前轮、上一轮及本次运行最近成功产物，并校验端口、准确 schema、条件重叠与来源语义。它们描述方法预期；真实资产仍以 context 收据为准。新声明参与新方法 hash；旧版本与旧运行不回写。

## 保留的限制

1. 当前宿主只能执行匹配当前部署定义的已发布版本。历史不可变执行包加载、多个选题独立并行与取消尚未交付。
2. 版本页可按准确版本归集已有运行和评价；预先冻结的验证集合、跨案例统计与公平的跨版本比较尚未交付。
3. 方法图来自显式流程声明；不能自动解析任意 `execute()`。通用的声明与真实运行差异检查仍待实现。
4. schema、方法、展示绑定分步骤写入，发布可幂等重试，尚非一个跨步骤原子事务。若中途失败，须重试确认发布完成。
5. 本轮技术验证不证明内容质量提升。VM、B3、多 workflow 协同均不在本轮范围。
