# Workflow Spaces

`@signal-room/workflow-spaces` is the PostgreSQL-backed domain service for a long-lived business space. It stores published schema and workflow revisions, cases, frozen input manifests, runs, immutable asset versions, node contexts and sessions, reviews, comparisons, iterations, and adoption decisions. `@signal-room/workflow-postgres` remains the lower-level execution ledger. See the [implementation guide](../../docs/space-storage.md) for setup and recovery rules; [Workflow Space](../../docs/workflow-spaces.md) describes the wider product design.

The host creates and owns a `pg` pool and a `BlobStore`, then runs `migrateWorkflowSpaces(pool)` and the blob provider's migration. `PostgresBlobStore` is a 16 MiB-per-object baseline that stores actual bytes in PostgreSQL. Production-sized media needs a private durable `BlobStore` implementation; none is bundled. The host authenticates a `SpacePrincipal` and creates `WorkflowSpaceService(pool, blobs, principal)`. The service checks Space membership and roles. The database does not use RLS, so the host must not expose its pool or full service to a node.

Host code registers schemas, publishes a storage contract with each workflow version, creates a case and frozen input manifest, and starts a run. It starts each node with exact input asset version IDs, declared instructions and actual configuration. `nodeClient(spaceId, contextId)` returns only `read`, `readFull`, `submit`, and `act` for the validated context. `readFull` is denied for projected inputs; outputs must match declared slots, schemas, states and dependency slots. `act` currently permits only contract-authorized evaluation of bound assets. Human state transitions and adoption use the authenticated host service, not an Agent tool. `nodeReadTools(client)` provides a bound, read-only tool descriptor for an executor. `createSpaceRuntime(...)` bridges the existing core runner/store to Space records while keeping resolver and ledger access in trusted host code.

`createSpaceConsole(service)` is a read-only HTTP renderer, not an authentication server. Bind it to an authenticated principal inside the host's access boundary; a server with one bound service shared among unrelated HTTP users would share that principal's view.

The console accepts optional schema-specific readers keyed by `namespace@revision` through `createSpaceConsole(service, { readers })`; it falls back to the structured body and always escapes displayed text. The core bridge persists an observed Agent response with its core completion receipt, and persists a published asset with its core artifact receipt. A deterministic lost-acknowledgement regression checks that a durable Agent response can be replayed without a second runner call. Native SDK session resume and external tool exactly-once behavior are separate, unimplemented guarantees.

The full service, runtime ledger, context/session recording and workflow publication are host-only APIs. An Agent receives the restricted `NodeClient` or explicit tool descriptors. See [the implementation guide](../../docs/space-storage.md) for idempotency, unknown commit outcomes, configuration provenance and current limitations.

For deterministic PostgreSQL checks, set `WORKFLOW_TEST_DATABASE_URL` to a dedicated disposable test database and run `npm run test:spaces` from the `agent-workflow` root. The script fails when the variable is absent; it does not call a model. An opt-in, app-owned SIWC live producer and a fresh independent reviewer have also completed against synthetic assets, with bound reads, visible events and persisted outputs; neither constitutes human creative acceptance. Commands and environment inputs are in the [implementation guide](../../docs/space-storage.md).
