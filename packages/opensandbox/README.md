# OpenSandbox Agent attempt adapter

`createOpenSandboxAgentRunner` creates one OpenSandbox 1.1.1 sandbox for each `AgentRunRequest` attempt. The official Agents SDK and SIWC credentials stay on the host. Call `openSandboxAgentConfig(profile, endpoint)` when defining the Agent and merge its digest into `config`; the runner rejects a different environment before creating a sandbox. The host fixes a digest-pinned image, resources, TTL, default-deny egress and exact command registry.

`prepare` stages trusted input bytes after the workspace exists. `hostTools(request)` adds attempt-bound host business tools; duplicate tool names fail before the SDK starts. `finish` can read and validate bytes before remote cleanup. It must have **no durable side effects**: publish through the workflow after the runner returns, with a separate server-side attempt fence for any host tool that does have effects. Abort races uncooperative callbacks and starts remote kill, but JavaScript cannot forcibly stop a callback already running; late results are ignored, while its external side effects still require a fence.

Remote `write_file` path checks are lexical application controls. A model-written script is arbitrary code inside the sandbox and can create symlinks or access other container paths. Do not mount host credentials or private assets in the image. `read_file`/`read_image` use byte-preserving `Range` streaming and reject an oversized response while reading; OpenSandbox 1.1.1 `offset`/`limit` parameters count lines, so they cannot enforce a byte bound. A single transport chunk can still exceed the application limit before it is rejected. Fixed `exec_allowed` commands take no model-supplied arguments. A command transport error latches the attempt terminal; there is no automatic replay. A create transport error is reported as `OPEN_SANDBOX_CREATE_OUTCOME_UNKNOWN`; reconcile by attempt metadata before any manual retry.

Kill and close each have a bounded wait (default 10 seconds, maximum 30 seconds). A successful Agent result returns with `metadata.sandboxCleanup` even if cleanup failed. The `sandbox.cleanup_failed` event is attempted and `metadata.cleanupEventRecorded` reports whether it was saved. Background cleanup may continue after a timeout. Durable sandbox leases, orphan recovery, transport byte limits, host-tool fences, and atomic asset publication belong in the integrating host.

`examples/opensandbox-smoke.mjs` exercises the adapter with no model or server. `examples/opensandbox-csv.ts` is opt-in and requires a live OpenSandbox service, SIWC authorization, and PostgreSQL. No import starts remote work.
